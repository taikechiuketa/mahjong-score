# たけチャート 画面説明・使い方

[リポジトリのトップへ](../README.md)

## 1. 入口とログイン

[記録画面](https://taikechiuketa.github.io/mahjong-score/)を開くと、未ログインならメール・パスワードのログイン画面が表示されます。ログイン済みならDBの最新データを自動で読み込みます。「DBから読み込む」という通常操作は不要です。データがない場合は新しいセットの開始待ちになり、サンプルのプレイヤーは生成しません。

ログイン画面の「成績を見る（ログイン不要）」から[公開成績](https://taikechiuketa.github.io/mahjong-score/results.html)へ移れます。公開成績からは「対局を記録する（ログイン）」で戻れます。

端末とDBが異なり、未送信の入力がある場合は自動で上書きしません。「DBの保存データで開く」「端末のデータで再開」から選びます。どちらを選んでも両方の復旧コピーはこの端末に残ります。端末を選んだだけではDBへ送信しません。

## 2. 4つの画面

| メニュー | 内容 |
| --- | --- |
| 入力 | セット設定、参加者、半荘スコア、チップ・最終精算、セットの保存・終了 |
| 成績 | 保存済みセットの通算成績、期間・種目別集計、レーティング、個人成績 |
| 履歴 | セットの検索・詳細・編集・削除、共有、雀簿データ追加 |
| 設定 | プレイヤーマスター、JSON保存・読込、バックアップ・復元、復旧コピー、接続の詳細、ルールへのリンク |

画面上部にログイン状態・保存状態を表示します。「この端末からログアウト」も上部にあります。

## 3. 対局を記録する

「新しいセット」で開始し、「プレイヤーを選ぶ」で参加者を追加します。倍率とチップレートは入力画面で設定します。

セット設定の「日付・番号を編集」で対局日と連番を変更できます。連番は1以上の整数で、同じ日付・番号は指定できません。「変更する」で端末に保護され、「セットを保存」で履歴・DB・公開成績へ反映します。過去のセットは「履歴 → 編集」から同じ操作を使います。参加者・点数・チップは維持されます。日付は期間別集計、日付・番号の並び順はレーティングの計算順に影響します。保存済みセットの日付・番号を変更した場合は共有URLも変わるため、変更後のリンクを共有し直してください。プレイヤーマスター全体の登録・編集は「設定」にあります。

| 操作 | 結果 |
| --- | --- |
| 半荘を追加 | スコア表の下に行を追加します。半荘ごとに三麻・四人三麻・四人麻雀を選べます。 |
| 点数入力 | 整数で入力します。必要人数より1人少ないところまで入力し、残りの空欄を選ぶと合計0の点数を補完します。抜け番は長押しで設定・解除します。 |
| チップ入力 | セットの最後に増減枚数を入力します。マイナスは赤字。合計が0でなければ保存時に確認します。 |
| セットを保存 | 端末の履歴に保存したあと、DB保存と公開成績への反映を行います。セットの入力は続けられます。 |
| セットを終了 | 履歴へ保存して進行中セットを閉じ、DBに反映します。 |
| 新しいセット | 進行中があれば確認後に履歴に保存し、次のセットを開始します。 |

半荘スコア表は内部スクロールになっています。半荘が増えても上の対局者名と左の半荘番号が固定され、累計ptも下に表示されます。「半荘を追加」すると表の中が末尾へ移動します。

入力途中は端末に一時保存されます。端末保存だけでは別端末や公開ページには反映されません。履歴の編集中も入力を端末で保護し、「設定 → 保護した入力を確認」から再開できます。

「保存済み・公開成績にも反映しました」が成功表示です。DB保存だけ成功した場合は「DBに保存済み・成績ページへの反映待ち」と表示します。「設定 → 接続・保存の詳細 → 入力を保存・保存を再試行」から再送信できます。初回の読み込み失敗、接続失敗、他端末の先行更新では送信を停止します。

## 4. 成績・履歴・共有

成績は端末の履歴に保存済みのセットを集計し、未保存の進行中入力は含めません。DB保存が未完了の場合、公開成績にはまだ反映されません。レーティング・個人成績も同じ保存済みセットを対象にします。「通算成績」タブ内の集計期間・種目で絞り込み、見出しで並べ替えられます。プレイヤー名から順位分布、対戦相手別成績、ポイント・チップ・収支とRの推移を確認できます。

レーティングの「現在R」「対象半荘」「直近の増減」は常に全期間から計算します。通算成績の集計期間は適用されません。表の下にある「R推移の表示期間」は推移グラフだけに適用され、通算成績の期間とは別に保持されます。レーティング表から開く個人成績も全期間です。

履歴には進行中セットも表示します。過去セットの「編集」から入力へ移り、「セットを保存」で修正を反映します。編集を取り消す前の内容も復旧用に保護します。

各セットを開くと「このセットの着順回数・割合」で、各人の有効半荘数と1〜4着の回数・割合を確認できます。必要人数の整数スコアがそろった半荘だけを対象にし、抜け・未入力は除外します。同点は同順位です。三麻のみの参加者の4着は「—」と表示します。

同じセット内の「半荘別スコア」を開くと、対局者名と半荘番号を固定したスクロール表を表示します。公開成績の履歴・セット共有ページにも同じ分析とスコア表があります。

保存済みセットでは進行中でも共有リンクを利用できます。DB保存・公開反映の完了を確認してから共有してください。同じ日付・伝票番号が重複する場合はリンクを表示しません。既存の共有URLは継続利用できます。

## 5. 設定とデータの復旧

「JSON保存／読込」は現在のセットだけ、「全データをバックアップ／バックアップから復元」は現在のセット・履歴・プレイヤーマスターが対象です。全データの復元は件数を確認してから端末とDBに反映する操作です。復元前の端末データも保護します。

「復旧コピーを書き出す」は、改修前・DB読み込み前・送信前などの複数コピーをまとめた復旧ファイルを出力します。このファイルは通常の全データバックアップとは形式が異なります。内容の確認・支援を受ける際にも使えます。

「復旧コピーから端末に戻す → コピーの一覧を表示」で日時とセット数を確認し、「選んだコピーを端末に戻す」で復元できます。こちらはDBには自動送信しません。内容を確認したあと、必要な場合だけ「入力を保存・保存を再試行」を押してください。

コピーは同じブラウザの端末内に保持されます。ブラウザのデータ削除や端末故障では失われ得るため、全データのバックアップと復旧コピーの書き出しも利用してください。復旧コピーを作れない場合は、DBデータの読み込みによる置換・送信を止めます。

## 6. ログアウトとルール

上部の「この端末からログアウト」を押します。未送信入力があれば、保護してログアウトするか確認します。DBへは勝手に送信しません。他の端末のログインは維持します。端末内のデータは旧版との互換性・入力保護のため残りますが、改修版の管理画面はログインしないと開けません。端末データの暗号化を提供する仕組みではありません。

[ルール・点数表](https://taikechiuketa.github.io/mahjong-score/rules.html)はログインなしで参照できます。編集は記録画面とログインを共通利用します。保存前に旧本文を端末へ保護し、公開前の確認を表示します。

## 7. 参加募集・チャット・通知

記録画面・公開成績の「参加募集・チャット」から開きます。管理者ログイン・利用者登録は不要です。募集者・参加者・投稿者は自由な表示名を入力します。名前は端末に保存しますが、本人確認を行うものではありません。

「＋ 募集する」で、募集者名・タイトル・開催日・開始／終了時間・場所・麻雀の種類・集まっている人数・あと何人募集するか・補足を入力します。場所の初期値は「たけちゃお」で、自由に変更できます。日付はカレンダー、時間は時刻選択（空欄は未定）、麻雀の種類・人数は選択式です。公開に管理者の承認は不要です。「新しい募集を仲間に通知する」がONなら募集通知を許可した端末へ通知します。投稿した端末自身には新規募集通知を送りません。

募集一覧には今後の締め切っていない募集（満員を含む）を表示します。「過去・締切済みも表示」で履歴も確認できます。詳細の「この募集に参加する」は下の表示名で参加を記録します。募集者と最初から決まっている人数は既存参加者として数え、新規参加の残数を減らします。満員や締切後は追加参加できません。「参加を取り消す」で枠が戻ります。募集者は同じ端末から内容を編集・締切・再開できます。

募集詳細のチャットでは集合時間などを相談できます。表示中は約5秒ごとに更新し、最新100件を表示します。自分の投稿は削除でき、募集者はその募集の投稿を削除できます。本文は1000文字まで。「募集リンクをコピー」で募集を直接開くURLを共有できます。端末のデータ削除・別ブラウザ・別端末では同一人物として扱われません。

募集・参加した端末は、その募集の新着通知が自動でONになります。「この募集の新着通知を受け取る」で募集ごとに切り替えられます。参加取消だけではチャットの通知設定は変わりません。実際に受信するには端末の通知許可と通知登録も必要です。

「通知設定・ガイド」から「募集通知をONにする」「この端末の通知をOFF」「テスト通知を送る」を利用します。OFFはこの端末の募集・チャット通知両方を解除します。テストは通知サービスへの送信受付と、端末での実表示を分けて案内します。

- iPhone／iPad：iOS／iPadOS 16.4以降。Safariの共有メニューから閲覧ページをホーム画面に追加し、追加したアプリを開いて通知を許可します。
- Android：対応ブラウザで開き、通知を許可します。必要ならホーム画面への追加／インストールも行えます。
- ガイドは端末を推定して表示しますが、手動切替も可能です。OS・ブラウザ設定、集中モード、通知が届かない場合の確認方法を案内します。

募集・チャットはこのページを開いた人が閲覧できます。成績ページの公開設定やバックアップは募集・チャットには適用されません。

### 通知の送信エラーと再試行

通知先の登録とテスト通知の送信は別処理です。サーバー側の認証・暗号化・通信に問題がある場合は端末の再登録を促しません。期限切れの通知先に限りOFF→ONによる再登録を案内します。テスト通知は30秒以上間隔を空け、成功受付した回数のみを1時間5回の上限に数えます。待機中はボタンに残り秒数を表示し、回数制限時は再試行までの秒数を表示します。通知がOFFの間はテストボタンを無効にします。

### 募集の削除と参加登録

募集者の端末では「募集を削除する」が表示されます。確認後に削除すると、通常一覧・過去一覧の両方から消え、募集リンクから参加者一覧やチャットも閲覧できなくなります。「締め切る」は履歴を残して参加受付だけを停止する操作です。削除の取り消し画面はありません。

他の端末・ブラウザでは、募集中の詳細に「参加する名前」と「この募集に参加する」が表示されます。名前を入力して押すと参加者として名前が並び、残り人数が減ります。募集者側の動作確認には募集リンクを別ブラウザやシークレットウィンドウで開いてください。普段使っているブラウザのデータを消す必要はありません。募集者自身は最初から参加予定人数に含まれます。

新規募集の通知は「○○さんが参加者を募集中！」と日時・場所・残り人数を表示します。チャットの通知は「『募集タイトル』に新着メッセージ」と投稿者・本文の先頭部分を表示します。同じアプリの通知ですが内容と対象者は別で、どちらもタップすると該当募集が開きます。自分の募集・自分の投稿は自分の端末には通知しません。

### 参加・参加取消の通知

誰かが「この募集に参加する」を押して参加が確定すると、通知をONにしている募集者の端末へ「○○さんが参加しました」と残り人数を知らせます。最後の枠が埋まった場合は「メンバーがそろいました！」と表示します。

「参加を取り消す」で実際の登録が取り消された場合は「○○さんが参加を取り消しました」と残り人数を知らせます。締切済みの募集は、取り消しても自動では再開せず「募集は締切済みです」と通知します。いずれもタップすると該当募集を開きます。

参加・取消の通知先は募集者のみです。端末全体の通知がONなら受け取れます。募集ごとのチャット通知設定とは独立しています。二重押し・満員での参加失敗・未参加者の取消では通知しません。
