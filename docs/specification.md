# たけチャート 機能・データ仕様書

[画面説明・使い方](screen-guide.md) · [リポジトリのトップへ](../README.md)

2026年11月9日の公開コードを基準とする。画面の操作は画面説明に記載し、ここでは集計条件とデータの扱いを定義する。

## 1. 構成

| ファイル | 役割 |
| --- | --- |
| [index.html](../index.html) | スコア入力、プレイヤーマスター、集計、履歴管理、JSON入出力、管理者向けDB同期 |
| [results.html](../results.html) | 保存済みセットの公開成績、個人成績、レーティング、セット共有 |
| [rules.html](../rules.html) | ルール本文と点数表画像 |
| [app.webmanifest](../app.webmanifest)・[viewer.webmanifest](../viewer.webmanifest) | 入力画面・閲覧画面のWebアプリ用メタデータ |

HTML・CSS・JavaScriptをGitHub Pagesで配信する。入力データの端末保存はブラウザの `localStorage`、クラウド保存と閲覧用配信はSupabaseを使う。

## 2. セットと入力

- セットは対局日、伝票番号、ポイント倍率、チップレート、プレイヤー、半荘を持つ。半荘は種目とプレイヤーごとのポイントを持つ。未入力と抜け番（`skip`）を区別する。
- 種目は三麻（`normal`、3人）、四人三麻（`north`、4人）、四人麻雀（`yonma`、4人）。人数はスコアを記録する人数。同じセット内でも半荘ごとに種目を選べる。
- 点数は整数。入力人数不足、整数以外、合計が0でない半荘を警告し、保存時に確認する。最後の点数の自動補完は入力済みポイント合計の符号を反転する。
- 精算値（画面ではpt表示）は `ポイント合計 × ポイント倍率 + チップ増減 × チップレート`。
- 履歴への保存は内部の `archiveId` で追加・更新を識別する。終了時は履歴へ保存後、日付と伝票番号を持たない待機状態へ移る。
- プレイヤーの集計はマスターIDを優先し、未紐付けの既存データでは名前を使う場合がある。ランキング表示設定はランキング掲載を制御する。公開済みのセット詳細には参加者名とスコアが含まれる。

## 3. 集計・ランキング・レーティング

| 項目 | 仕様 |
| --- | --- |
| 期間 | 全期間、月間ランキング、今月、前月、今年、範囲指定。指定期間は両端の日付を含む。月間ランキングの対象月は当月と履歴の月から選ぶ。 |
| 通算成績 | ポイント合計を基準に初期表示し、列見出しで並べ替え可能。種目指定時、チップはその種目だけで構成されたセットの分を含める。 |
| 順位 | 整数スコアがそろった半荘で、自分より得点が高い人数に1を足した順位を使う。同点は同順位。 |
| 個人成績 | 種目別の順位分布、トップ率、平均順位、ラス率、対戦相手別成績と、期間内の累積ポイント・チップ・収支の推移を表示する。 |
| レーティング | 総合・種目別に初期値1500から再計算。対局日、伝票番号、セット内の半荘順で処理する。規定人数の整数スコアがあり、選手IDが重複せず、合計が0の半荘が対象。対象20半荘未満は暫定表示。 |

レーティングは半荘前の各選手の値で相手ごとの期待値を計算する。期待値は `1 / (1 + 10^((相手R − 自分R) / 400))`、実績値は勝ち1・同点0.5・負け0。半荘の増減は、各相手に対する「実績値 − 期待値」の平均に24を掛けた値。現在Rは選択種目の全対局を使い、期間条件はR推移の表示に適用する。

## 4. データの保存・移行

| 機能 | 仕様 |
| --- | --- |
| セットJSON | 現在のセットを出力。読み込み時は形式と置換の確認を行う。 |
| 全データのバックアップ | `format: "takechao-backup"`、`version: 1`。保存日時と `current`、`history`、`master` を含む。 |
| 全データの復元 | 形式と各データを検証し、端末内の3種類のデータを置き換える。書き込み途中で失敗した場合は書き込んだ項目の復元を試みる。 |
| 雀簿取り込み | 貼り付けたテキストを解析し、対局種目を指定してプレビュー後に履歴へ追加する。プレイヤーの紐付け・補完を行う。 |
| 管理者同期 | Supabaseの認証を使う。管理用スナップショットは所有者と更新日時を条件に更新し、別端末による先行更新を検知する。同期失敗時も端末データは保持する。 |

## 5. 公開データ・共有・転送量

- 同期時に、管理用スナップショットとは別に保存済みセットから公開用データを組み立てる。公開側は `sets-v2` を読み、画面で成績を集計する。
- セット共有URLは `results.html?date=対局日&set=伝票番号`。同じ日付と伝票番号でセットを一意に特定できる場合にリンクを表示する。公開側で表示するには、そのセットの同期が必要。
- 公開成績ページは初回に公開データを取得し、表示中は30秒ごとと再表示時に更新を確認する。取得済みの更新日時をクエリ条件に入れ、同じ更新日時の行は返さない。変更があった場合は新しい公開データを取得する。セット共有ページも同じ取得処理を使う。
- 公開ページの確認では、初回表示、更新なし、更新あり、セット共有URLの4通りを確認する。変更なしの応答本文は空配列（`[]`）。

## 試作ブランチの差分

- 試作入力画面の設定、現在のセット、履歴、マスターは試作用の名前空間に保存し、グループIDで分離する。初期グループは「おためし卓」。通常版の保存キーやSupabaseは試作入力画面から参照しない。
- テーマは紅・藍・深緑。ルールはプレーンテキストとして表示し、集計には影響しない。ロゴはPNG/JPEG/WebP、点数表は同形式またはPDF、各512 KiBまで。
- バックアップ形式は既存互換とし、試作のグループ設定・添付は含まない。クラウド権限と共有ページは今後の実装対象。
